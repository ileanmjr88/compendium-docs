This page reflects what Compendium does today versus what's planned for
the next releases.

## v0.1 (current)

The foundation: pin a toolchain in `compendium.toml`, install it
under `~/.local/compendium/`, activate it with one shell command.

**Languages.** C and C++ (via `gcc` and `clang`), Python, Node, Go, and
the embedded cross-compilers `arm-none-eabi-gcc`, `aarch64-none-elf-gcc`,
and `riscv-none-elf-gcc`.

**Tools.** Build (`cmake`, `ninja`, `ccache`, `pkg-config`, `m4`, `bison`),
linters and formatters (`golangci-lint`, `ruff`), package managers
(`vcpkg`, `uv`, `pnpm`), embedded (`openocd`), release tooling
(`goreleaser`), and `realpath`.

See [Available tools](/reference/available-tools/) for the live list of
versions in the registry.

**Package managers.** `vcpkg` is wired up (per-project install dir,
`VCPKG_ROOT` and `VCPKG_INSTALLED_DIR` exported on activate). Other
keys in `[packages]` are parsed but not yet consumed.

**Per-project environments.**

- Python: project-scoped `venv/`, `VIRTUAL_ENV` and `UV_PROJECT_ENVIRONMENT` exported on activate.
- Go: project-scoped `GOPATH` and `GOBIN`, both on `PATH` after activate.

**Commands.** `install`, `activate`, `deactivate`, `env`, `status`,
`versions`, `version`.

**Registry.** Public registry only.

**Platforms.** macOS and Linux.

**License.** Apache-2.0 starting with v0.1.2. v0.1.1 and earlier stay
under GPL-3.0. See [ADR 0001](/adr/0001-relicense-to-apache/).

## v0.2 (in progress): the lockfile

`compendium.lock` records exactly what `compendium.toml` resolved to, so
any machine can reproduce the same environment.

- **`compendium.lock`** — exact versions, download URLs, checksums, and
  sizes for every pinned language and tool. `compendium install` writes it
  on the first run and follows it after that, re-resolving only what
  changed in `compendium.toml`.
- **Cross-platform pinning** — each platform your team installs on is
  added to the lock. Install on a Mac, then on Linux, and the lock pins
  both. A version bump re-resolves every platform already in the lock.
- **`install --frozen`** (alias `--locked`) — for CI: fail instead of
  updating the lock when `compendium.toml` has drifted from it.
- **Version bumps keep platform coverage** — if the registry has no build
  of the new version for one of your platforms, the install fails.
  `--allow-partial` accepts the gap.
- **Drift in `status`** — reports when `compendium.toml` and
  `compendium.lock` disagree, and when an ecosystem lockfile such as
  `go.sum` changes. Exits non-zero on drift.
- **`[packages]` points at resolved files** — `go.sum`,
  `package-lock.json`, `uv.lock`, and `poetry.lock` instead of `go.mod`,
  `package.json`, and `pyproject.toml`. `vcpkg.json` and
  `requirements.txt` stay the same. This is a breaking change.
- **`compendium verify`** — offline check that the lock is complete: every
  pinned item has artifacts for every platform the lock covers, every
  artifact has a checksum, ecosystem lockfiles still match their recorded
  digests, and the lock covers the platform you're on.
- **Registry license metadata** — each registry entry records the tool's
  SPDX license ID, a license URL, and a source URL.

## v0.3: git hooks

Compendium runs your project's git hooks inside the pinned environment.

- **Git hook runner** — `compendium install` installs the hooks declared
  in `[hooks]` of `compendium.toml`, and each one runs with your pinned
  tools. The section is parsed in v0.1 but nothing runs yet.
- **`pre-commit` first**, plus a small set of others: `commit-msg`,
  `pre-push`, and `post-merge`.
- **Auto-activate on branch switch** — a `post-checkout` hook runs
  `compendium activate` when you switch branches, so the environment
  follows your code.

## v0.4: new tools in the registry

More languages, toolchains, and build systems, plus running your
project's package managers.

- **Java** and its build tools.
- **Kotlin** — JVM language, builds on the Java work.
- **Rust** — `rustc` and `cargo` as one language entry.
- **Zig** — systems language adjacent to C/C++; `zig cc` also works as a
  C/C++ cross-compiler.
- **Bun** — JavaScript runtime that bundles its own package manager,
  bundler, and test runner.
- **ESP32 / Xtensa toolchain** (`xtensa-esp-elf-gcc`) — completes the
  embedded cross-compiler set.
- **More C/C++ build systems** — Meson, Autotools, raw Makefiles, and b2
  (Boost).
- **`install --with-packages`** — opt-in, off by default. Runs the
  ecosystem package managers for `[packages]` (npm, pip, uv, poetry,
  vcpkg, cargo, Go modules). When an ecosystem lockfile changes, only that
  ecosystem runs again.

## v0.5: built-in C/C++ library manager

The first parts of a Compendium-native C/C++ library manager.

- **`[deps.*]` in `compendium.toml`** — declare C/C++ libraries in the
  same config as your toolchain.
- **Patch infrastructure** for C/C++ dependencies — declared per
  dependency, applied in order before the build, fails hard on conflict.
  Patch contents are hashed into the lockfile for reproducibility.
